{# dashboard.html - Clinical Staff Management landing page. Server-rendered shell + HTMX for the live bits. The page shows ONE list, chosen by the acting role (the `role` string app.py passes in): doctor -> assigned patients whose assessment is still open nurse -> that nurse's own care-task list specialist -> consultations still pending a recommendation app.py hands us the backend JSON untouched as `data`. Depending on which backend list the "/" route fetched, that dict carries one of: data.clinical_records (list) data.care_tasks (list) data.consultation_requests (list) The backend has already scoped each list to the current role, so we just render whatever arrived - no identity filtering happens here. HTMX: * the role switch (header) re-requests "/" with ?role=... and swaps * the list region polls "/" every 30s and swaps itself, so a task completed elsewhere shows up without a full reload Every hx-get hits this same "/" route; hx-select pulls just the fragment being swapped out of the full page the route returns. "Overdue" depends on the current time, which the server side of this route does not pass in. A small script at the end of reads each row's data-due timestamp, flips its status word to "Overdue", and updates the Overdue / Ratio metrics. It re-runs after every HTMX swap.
